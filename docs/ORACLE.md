# What the evidence establishes

An accepted close establishes a relationship between a frozen set of commitments,
the authenticated trustee publications and the stored aggregate. An accepted
badge establishes an opening and a threshold inequality under the circuit and
setup assumptions. Public verifier co-signatures bind a statement to the round's
allowlist. None of these establishes what a kiln emitted.

The executable mechanisms and their measured tests are in [CRYPTO_SPEC.md](CRYPTO_SPEC.md),
[CONTRACTS.md](CONTRACTS.md), [PHASE4_GATE.json](PHASE4_GATE.json) and
[PHASE6_GATE.json](PHASE6_GATE.json). Application curve code and the contributed
setups have not received an independent production audit.

| Boundary | Current control | Residual trust or missing assurance |
| --- | --- | --- |
| Physical activity to annual report | No real plant measurement is ingested. All evaluated PDFs are generated and watermarked. | Instruments, calibration, completeness, fraud, emissions attribution and verifier diligence remain outside the cryptographic protocol. |
| PDF to proposed fields | Local model returns schema-checked values and page/line proposals. | The model makes numerical and citation errors. The small shared-layout evaluation does not establish real-report accuracy. |
| Proposal to accepted source tokens | Code parses exact labelled source tokens; bounded repairs are disclosed; ambiguous or changed numbers remain blocked. | A faithfully read source can itself be false or omit relevant processes. Scanned reports need a separate validated OCR workflow. |
| Values to physical plausibility | Stoichiometry, sourced fuel factors, unit/range checks and scoped review flags. | The direct fossil/process CO2 model omits several accounting cases and is not a complete regulatory monitoring plan. |
| Review to sealing | A named officer signs the exact report/review/round binding; overrides require written reasons. | Current names and synthetic actors are not identity or accreditation credentials. Test signatures are explicitly marked automated. |
| Verifier statement to commitment | Actual ECDSA and ML-DSA co-signatures, input-validity proof and allowlist checks. | A compromised or dishonest authorised verifier can attest false reports. ML-DSA verification is off-chain. |
| Individual data to sector population | Public cohort root, common receipts, minimum size and a declared denominator. | The regulator selects the cohort and denominator. Neither proves completeness or statistical representativeness. |
| Aggregate to official use | Reproducible public evidence and an engineering dossier. | Authorities decide acceptable boundaries, population, assurance and official submissions. No process integration or acceptance exists. |

Fuel factors and process-method caveats are sourced in [S23–S29](SOURCES.md).
The [CBAM calculation regulation](https://eur-lex.europa.eu/eli/reg_impl/2025/2547/oj/eng)
(S15) requires programme-specific boundaries, functional units, monitoring and
attribution. The [TR-ETS procedures](https://iklim.gov.tr/db/turkce/duyurular/files/Yay%C4%B1mlanan_%20TR%20ETS%20Usul%20ve%20Esaslar.pdf)
(S16) distinguish sub-installations and allocation rules. A generic plant E/P
pair is not automatically a compliant input to either process.

The live browser flow is explicitly different from report review: it is manual
SIMULATED input with a signed declaration that no report validation was performed.
Its co-signature demonstrates the protocol mechanics, not verified report truth.
The report workflow's signed source/review hashes must not be used to describe
the manual live flow as a physical verification engagement.
