# Demonstration trusted setup

These are real Groth16 parameters and checks, not a simulated verifier. The
circuit-specific contribution is generated by one operator for this demonstration.
There is no claim of an independent project multiparty ceremony or production
trustworthiness. Synthetic proving inputs are separate, explicitly SIMULATED files.

Public phase-1 source: [Hermez power-15](https://circom.info/powersOfTau28_hez_final_15.ptau).
Published digest source: [snarkjs table](https://raw.githubusercontent.com/iden3/snarkjs/master/README.md)
(S20, accessed 2026-10-21).

```text
BLAKE2b-512
982372c867d229c236091f767e703253249a9b432c1710b4f326306bfa2428a17b06240359606cfe4d580b10a5a1f63fbed499527069c18ae17060472969ae6e
```

The public file has original ceremony power 28, trimmed to power 15. Its complete
contribution and prepared-parameter verification passed; see
`ptau-verification.log` ending in `FULL_TRANSCRIPT_VERIFICATION=PASS`. All 55
contributions were checked. The optional native BLAKE2b loader accelerates only
the enormous repeated-point initial hash, without changing inputs, digest size,
field operations, pairing checks or verification branches. It checks native
OpenSSL output against Noble across empty, boundary and streamed input sizes and
refuses to patch an unexpected upstream source. Run without the loader to use
the unmodified JavaScript hash, at greater runtime cost.

Rebuild from source:

```sh
make bootstrap
make setup-circuits
make test-circuits
```

The setup command downloads and checks the public file, verifies it, compiles
the circuits and generates a fresh, OS-random project contribution. Entropy is
not passed on a shell command line or saved in logs. Keys generated by a rerun
will differ; **the checked-in Solidity verifier must be regenerated with its
matching proving key**. Do not mix keys, verification JSON or generated contracts
from different runs. The setup command exports these together and verifies each
contributed key against its R1CS and ptau.

Public ptau and zkey binaries are ignored by Git due to size. They are public
proving parameters, not signing secrets. Logs, public verification keys, generated
Solidity and a hash manifest form the review record once the gate completes.
This repository does not yet publish downloadable pinned proving-key releases;
deployment must not start before such a matching bundle is available.

The exported verifier is generated code. No always-true replacement or mocked
proof is permitted. A passing witness is not counted as a verified proof; the
separate proof tests must generate and verify real Groth16 objects and reject
mutated public inputs.
